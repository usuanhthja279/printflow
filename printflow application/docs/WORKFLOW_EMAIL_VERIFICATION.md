# Lifecycle email and local UI workflow — 24 October 2026

## Implemented events

A newly created enquiry sends a customer acknowledgement and a team alert. Accepting intake notifies the customer and team. Issuing the quotation sends its exact version and customer account access instructions; an unknown customer receives a private one-time setup link in that quotation email. Portal quotation acceptance/change requests notify both sides. Artwork requests, proof sharing, proof comments, customer change/rejection/approval and evidenced offline approval queue their corresponding notifications. Confirmed production start, quality completion, dispatch, delivery, delivery issue/resolution and automatic completion queue customer/team emails.

Email remains restricted to the selected real local test inbox, your-test-inbox@example.com. Team alerts default to the configured sending account, with assigned staff addresses added where applicable; APP_OWNER_NOTIFICATION_EMAIL can override the owner inbox. Fictional/non-allowed and historical messages are held. System SPRING_MAIL_USERNAME / SPRING_MAIL_PASSWORD remain the credential source; no plaintext password is emailed or stored in the quotation.

## Account setup

A quotation creates an inactive pending customer account only when the email has no existing account. A strong random, unknown password hash prevents sign-in before setup. The email contains the sign-in address and a 24-hour single-use setup URL, with its token in the fragment. The database stores only the token digest. The customer chooses a 14–72 UTF-8 byte password and accepts the current privacy notice; setup verifies mailbox ownership and activates the account. Reuse/expiry fails. Existing verified accounts retain their password and administrator-disabled accounts are not re-enabled. Staff-account email collisions never create customer access. Existing linked ownership is preserved.

## UI path

1. Submit the enquiry using the allowed inbox. Owner opens **Enquiries**, accepts it and sends a quotation.
2. Open the quotation email’s account setup link if needed; choose a password and consent, then sign in. Existing customers sign in normally. The enquiry is linked automatically through the verified/pending customer identity.
3. Customer accepts the quotation. Open **Live works**. Owner/assigned designer uploads a clean design and shares the numbered proof; customer reviews, comments or approves.
4. After the exact current proof is approved, the owner enquiry shows **Production & delivery**. Enter a customer-visible note, acknowledge the confirmation, and choose **Start production**. Resolve any outstanding quotation/amendment first.
5. Owner or assigned printer confirms production and quality complete. Owner or assigned delivery staff confirms dispatch, then actual delivery. Assign specialist tasks from the owner’s work panel; an unrelated staff member cannot advance the project.
6. Customer sees Delivered, under 48-hour review, and can report an issue. Owner resolves an issue with a note; review restarts. A server scheduler completes eligible work after 48 hours, survives restart and does not complete an open issue. No UI shortcut skips the review window.
7. Owner **EMAIL → Email activity → Refresh** shows queued/sent/held/failed, attempts and safe failure codes. Processing normally runs every 30 seconds. Sent means SMTP accepted; check Inbox/Spam for receipt. Setup links/credentials and message bodies are absent from the delivery log.
